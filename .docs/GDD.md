# Prowl's Moving Factory — 게임 디자인 문서 (GDD)

> 버전 0.3 · 2026-08-29
> 이 문서는 **게임 규칙과 용어의 단일 진실 원천**이다.
> 수치는 여기 쓰지 않는다(→ ScriptableObject / 밸런스 시트). 결정의 이유도 여기 쓰지 않는다(→ ADR).
> **여기 없는 규칙은 아직 존재하지 않는 규칙이다.** 구현 중 필요해지면 이 문서에 먼저 추가하고 구현하라.

---

## 1. 한 문장 정의

> **이동하는 적 스폰 지점 때문에 방어선을 계속 다시 짜야 하는, 호위형 타워 디펜스.**

역(逆)타워디펜스다. 적이 우리 진영에 오는 것을 막는 게 아니라, **우리 편(보호대상)이 반대편 출구까지 살아서 가게 만드는** 게임이다.

## 2. 용어표 (코드 식별자와 1:1로 대응한다)

**이 표의 오른쪽 영문명을 코드에서 그대로 쓴다. 동의어를 새로 지어내지 마라.**

| 한글 | 코드 식별자 | 정의 |
|---|---|---|
| 보호대상 | `Escortee` | 플레이어가 지켜야 하는 개체. 자동으로 경로를 따라 탈출 지점으로 간다. 죽으면 패배. |
| 탈출 지점 | `ExitPoint` | 보호대상의 목적지. 도달하면 승리. |
| 모체 / 추적자 | `MotherSpawner` | **처치 불가능한**, 이동하는 적 스폰 지점. 보호대상을 향해 느리게 따라가며 잡몹을 계속 뱉는다. 이 게임의 핵심 장치. |
| 잡몹 | `Enemy` | 모체가 스폰하는 일반 적. 보호대상보다 빠르다. 보호대상을 공격한다. 처치 가능. |
| 버스트 모드 | `BurstMode` | 모체가 **추적 에너지를 생산으로 전환**하는 상태. 이동을 멈추고 스폰 밀도를 올린다. **적 총량은 보존**되고 밀도만 바뀐다 (→ §7). |
| 마을 | `Village` | 맵에 고정 배치된 아군 유닛 고용처. 플레이어의 유일한 병력 공급원. |
| 유닛 | `AllyUnit` | 마을에서 고용해 배치하는 아군. 사거리 안의 적을 자동 사격한다. |
| 배치 슬롯 | `DeploySlot` | 유닛을 배치할 수 있는 격자 칸. 아무 데나 놓을 수 없다. |
| 행군 | `Marching` | 고용된 유닛이 마을에서 배치 슬롯까지 걸어가는 상태. **이 게임의 핵심 트레이드오프.** |
| 경로 그래프 | `PathGraph` | 맵 위의 이동 가능 노드와 엣지의 집합. |
| 지름길 | `ShortcutEdge` | 자원을 지불해야 열리는 엣지. **보호대상만 통행 가능, 적은 불가.** |
| 자원 | `Scrap` | **고철.** 단일 통화. 로봇을 격파하면 흩어지는 부품을 모은 것 (→ §10, §12). |
| 고양이 수인 | `CatFolk` | 병종 1. 근접 공격. 사거리 짧음 / 공속·행군 빠름. 블로킹이 아니다 (→ ADR-0010). |
| 쥐 수인 | `RatFolk` | 병종 2. 원거리 무기. 사거리 김 / 공속·행군 느림 (→ ADR-0010). |
| 여우 수인 | `FoxFolk` | 병종 3. **무희** — 주변 아군에게 **공격속도 버프**. 유닛형이라 고용·행군·재배치한다 (→ §11C). |
| 영웅 | `Hero` | **스토리 핵심 인물.** 스테이지를 관통하는 연속성을 담당한다. 세부 미정 (→ §15). |
| 로봇 | `Robot` | 적의 정체. 인류가 남긴 기계. 잡몹(`Enemy`)과 모체(`MotherSpawner`) 모두 여기 속한다. |
| 업그레이드 | `UnitUpgrade` | 배치된 유닛에 자원을 써서 강화한다. 즉시 적용. **병종을 바꾸지 않는다** — 같은 병종 내 심화다 (→ ADR-0009). |
| 공병 | `Sapper` | 자원으로 사는 **일회성** 유닛. 다리 또는 장애물을 놓는다. **걸어서 도착한다** (→ ADR-0013). |
| 다리 | `Bridge` | 공병이 놓는 **아군 통로**. 배치 가능 영역을 넓힌다. 지름길과 별개 (→ §11). |
| 장애물 | `Obstacle` | 공병이 놓는 구조물. 체력이 있어 적이 부순다. **차단이 아니라 시간 구매** (→ §11B). |
| 일회성 회복 | `HealItem` | 자원으로 사는 보호대상 회복. **지속 힐러는 없다.** 걸어서 도착한다 (→ §10). |
| 스테이지 | `Stage` | 한 판. 맵 + 경로 + 마을 배치 + 웨이브 설정의 묶음. |

## 3. 승패 조건

| 결과 | 조건 |
|---|---|
| **승리** | 보호대상이 탈출 지점에 도달 |
| **패배** | 보호대상의 체력이 0 |

그 외의 종료 조건은 없다. (자원 고갈, 시간 초과, 유닛 전멸은 **패배 조건이 아니다.**)

**보호대상 체력이 이 게임의 유일한 패배 조건이다.** 모체는 공격 대상이 아니고, 모체에게 잡히는 일도 없다.

- 체력은 **내부적으로 실수(float)** 로 다룬다. 사망 판정은 `hp <= 0f` (`== 0` 금지), 데미지 적용 후 0 미만 클램프.
- **UI 는 숫자나 정확한 % 를 노출하지 않는다. 구간(눈금 바)으로만 표시한다.**
  실질 여유는 `체력 / (적 마리 수 × DPS)` 라서 체감상 훨씬 촘촘하다 — 숫자를 보여주면 플레이어가 여유를 오독한다.
  정확한 값이 필요한 것은 밸런싱하는 사람이지 플레이어가 아니다.
- 표시 갱신은 **구간이 바뀔 때만** 한다 (매 프레임 갱신 금지).

## 4. 핵심 루프

```
[시작]
  보호대상 생성 → 경로를 따라 자동 이동 시작
  N초 후 모체 생성 (보호대상 뒤쪽)

[반복]
  1. 모체가 보호대상을 향해 이동 (보호대상보다 느림)
  2. 모체가 일정 간격으로 잡몹 스폰 (스폰 위치 = 모체의 현재 위치)
  3. 잡몹이 경로 그래프를 따라 보호대상을 추격 (보호대상보다 빠름)
  4. 플레이어가 마을에서 유닛을 고용 → 유닛이 배치 슬롯까지 행군 → 도착 후 사격 시작
  5. 모체가 이동하면서 스폰 위치가 바뀜 → 기존 배치의 커버 범위가 무의미해짐
  6. 플레이어가 새 위치에 다시 고용 (= 재배치 비용 = 자원 + 행군 시간)

[변수]
  보호대상이 특정 지점에 도달하면 모체가 버스트 모드 진입
  플레이어가 자원을 써서 지름길을 열면 보호대상이 앞질러 감 (적은 못 따라옴)

[종료]
  보호대상이 탈출 지점 도달 → 승리
  보호대상 사망 → 패배
```

### 이 루프가 만들어내는 긴장

플레이어는 **"지금 여기"가 아니라 "곧 저기"에 병력을 보내야 한다.** 행군 시간 때문이다.
모체가 이동하므로, 지금 위험한 곳에 병력을 보내면 도착했을 땐 이미 늦다.
→ **예측형 플레이.** 이것이 검증해야 할 1순위 가설이다.

## 5. 맵 / 좌표계

- **직교 격자(Rectangular Grid).** 1셀 = 월드 1유닛 = `Vector2Int` 1칸.
- 원점 (0,0) 은 맵의 좌하단 셀. X는 오른쪽, Y는 위쪽 증가.
- 프로토타입 맵 권장 크기: **32 × 18 셀** (16:9 비율에 맞음).
- 카메라: Orthographic, 회전 없음.

> ### 🔴 2026-08-29 변경 — 맵 확장 + 카메라 팬·줌 (→ ADR-0014)
> ~~"맵 전체가 한 화면에 들어온다. 스크롤 없음."~~ 은 **폐기됐다.**
>
> - **맵을 키우고 카메라 팬·줌을 도입한다.** 근거는 화면이 아니라 **핵심 루프 반복 횟수**다 —
>   경로가 짧으면 "모체 이동 → 배치 무의미 → 재배치" 사이클이 1~2회밖에 안 돈다.
>   **3~5회는 반복돼야** 이 게임의 차별점이 체감된다.
> - **좌표계는 그대로다.** 줌은 월드 좌표를 건드리지 않으므로 `GridSystem` 과 클릭 판정에 변경이 없다.
> - **32×18 은 단계 7(그레이박스 시연)까지의 크기**다. 확장은 P2 에서.
>
> **맵 저작 원칙 — 사이클과 지형을 같은 주기로 맞춘다:**
> ```
> 적 세대 교체 1회 = 루프 사이클 1회 = 목(choke) 하나 = 정비 구간 하나
> ```
> 경로 길이만 늘리지 말고 **사이클마다 목이 하나씩** 오도록 지형을 배치한다.
> 목이 없으면 배치가 정적이 되고, 사이클이 너무 길면 재배치가 노동이 된다.
>
> **⚠️ 팬이 들어오면 모체가 화면 밖으로 나간다.** 모체에게 실제로 잡히지는 않으므로
> **압박은 메커니즘이 아니라 화면이 만든다.** 모체가 안 보이면 쫓기는 느낌이 0 이 된다.
> → 화면 밖 모체 표시는 **편의 기능이 아니라 핵심 장치**다. 방향 화살표만으로는 부족하고
>   **거리 게이지 / 접근 시 화면 가장자리 반응** 수준이 필요하다.

> **쿼터뷰는 프로토타입에 없다.** 최종적으로는 카메라를 X축으로 기울이고 스프라이트를 빌보드로 세워 명일방주식 화면을 만들 예정이지만, 그것은 *표현 계층*의 문제다. 논리 격자는 처음부터 끝까지 직교다. (→ ADR-0002)

### 셀 타입

| 타입 | 의미 |
|---|---|
| `Blocked` | 통행 불가, 배치 불가 (벽/절벽/물) |
| `Ground` | 통행 가능, 배치 불가 |
| `Road` | 경로 그래프가 지나가는 칸. 통행 가능, 배치 불가 |
| `Buildable` | 통행 가능, **유닛 배치 가능** |
| `VillageSlot` | 마을이 놓인 칸 |

**경로가 맵을 좌우로 가른다.** 배치 가능 칸이 경로 양옆에 분산되어 있어서, 어느 쪽에 병력을 두느냐가 판단 대상이 된다.

## 6. 경로 그래프

선형 웨이포인트가 **아니다.** 분기가 있는 방향 그래프다. (지름길 기믹 때문)

- **노드(`PathNode`)**: 격자 좌표 하나에 대응. 경로의 꺾이는 지점과 분기점에 놓인다.
- **엣지(`PathEdge`)**: 노드 → 노드. 각 엣지는 **누가 통행할 수 있는지**를 플래그로 갖는다.

| 엣지 종류 | Escortee | Enemy | Ally(행군) |
|---|:---:|:---:|:---:|
| 일반 경로 | ✅ | ✅ | ✅ |
| **지름길** | ✅ (자원 지불 후) | ❌ | ❌ |
| 아군 전용 통로 (선택적) | ❌ | ❌ | ✅ |

- 보호대상은 그래프 위 **탈출 지점까지의 최단 경로**를 따라간다. 지름길이 열리면 경로를 다시 계산한다.
- 잡몹은 **자신의 현재 노드에서 보호대상의 현재 노드까지의 최단 경로**를 따라간다. 지름길 엣지는 탐색에서 제외된다.
- 아군 유닛의 행군도 같은 그래프를 쓴다. 마을 노드 → 배치 슬롯 인접 노드 → 슬롯.

> **중요:** 노드 수가 수십 개 수준이므로 매 프레임 다익스트라를 돌려도 무방하다. 하지만 **경로 재계산은 이벤트 기반**으로 한다 — 보호대상이 노드를 통과했을 때, 지름길이 열렸을 때, 잡몹이 스폰될 때. 매 프레임 재계산하지 마라.

## 7. 모체 (MotherSpawner)

이 게임의 **유일한 차별점**이다. 여기가 밋밋하면 게임이 밋밋하다.

- **처치 불가능.** 체력이 없다. 플레이어는 모체에 아무 영향도 줄 수 없다.
- 보호대상을 향해 **직접(경로 무시) 이동**할 수도, **경로를 따라 이동**할 수도 있다.
  → **프로토타입 기본값: 경로를 따라 이동.** 자유 이동은 나중에 실험한다. 파라미터로 전환 가능하게 만들 것.
- 속도는 보호대상보다 **느리다.** 절대 따라잡히면 안 된다(따라잡히면 게임이 성립하지 않음).
- 일정 간격으로 잡몹을 스폰한다. **스폰 위치 = 모체의 현재 위치.**
- 시각적으로 **한눈에 "저기가 적이 나오는 곳"임이 읽혀야 한다.** 유닛보다 크고, 스폰 직전 예고 연출이 있어야 한다.

### 버스트 모드 — **추적 에너지를 생산으로 전환** (2026-08-29 재정의)

모체가 추적을 일시적으로 포기하고, 추적에 쓸 에너지를 **생산에 몰빵**한다.
고장난 기계가 "화가 나서" 몰아치는 게 아니라 **자원 배분**이라 별도 설명이 필요 없다.

- **진입:** 보호대상이 지정된 트리거 지점을 통과 (스테이지 데이터에 정의). 같은 트리거로 재진입하지 않는다
- **효과:** 이동 정지 + 스폰 **밀도** 급증
- **⚠️ 적 총량은 보존된다.** 버스트는 총량을 늘리는 게 아니라 밀도만 바꾼다.
  총량이 늘면 순수 페널티가 되어 플레이어가 대비할 수 있는 게 없다.
  보존이어야 **"버스트 전에 미리 배치를 몰아둔다"** 는 대비 플레이가 성립한다
- **예고 = 모체가 멈추는 것 그 자체.** 별도 경고 UI 를 만들지 않는다
- **지속:** 시간 기반. 이후 추격 재개

**리듬 — 정비 타이밍은 버스트 중이 아니라 그 직후다:**
```
모체 정지(예고) → 대량 스폰(최대 부하) → 추적 재개(빈 구간 = 정비) → 평시 복귀
```

- 정지로 벌어진 거리가 그대로 **빈 시간**이 된다. 여기가 플레이어의 정비 구간이다
- **빈 구간에는 상한이 필요하다.** 너무 길면 게임이 죽는다
  → 추격 재개 시 모체 속도를 잠깐 올려 회수한다 (에너지를 다시 추적에 몰빵 — 설정상 대칭)
- **자기조절:** 버스트가 셀수록 벌어진 거리가 크고, 뒤따르는 휴식도 길어진다

> ### ⚠️ 모체 속도는 난이도 변수가 아니다
> 모체에게 보호대상이 잡히는 일은 사실상 없다. 모체는 공격 대상도 아닌 **단순 스폰 포인트**다.
> 모체와 보호대상 속도가 둘 다 고정이므로 **거리는 진행도의 함수**다.
> 거리로 인한 난이도 차이는 **스폰되는 적의 체력**으로 조절한다 (스폰 테이블에 진행도별 체력 열).
> **실시간 거리에 적 HP 가 반응하게 만들지 마라. 고무줄 난이도로 읽힌다.**

## 8. 아군 유닛

### 생명 주기

```
[고용 클릭] → Queued → Marching → Deployed(전투) → (Retired)
                                      ↑↓ (재배치, ADR-0008)
                                   Marching
```

| 상태 | 규칙 |
|---|---|
| `Queued` | 마을의 고용 쿨다운/큐 대기. (프로토타입에서는 즉시 통과 가능) |
| `Marching` | 마을에서 목표 슬롯까지 경로 그래프를 따라 이동. **행군 중에는 공격하지 않는다.** |
| `Deployed` | 슬롯에 자리 잡음. 사거리 안 적을 자동 사격. **스스로 움직이지는 않는다.** 단, 플레이어의 재배치 명령으로 `Deployed → Marching` **재진입**이 가능하다 (→ ADR-0008). |
| `Retired` | 회수/소멸. (→ 미결정 D-01) |

### 이동 중에는 통제권이 없다 (→ ADR-0008)

> **도착해서 자리를 잡아야 통제권이 생긴다.**

- **배치된 유닛** = 재배치·회수 가능
- **이동 중(`Marching`)** = **확정.** 취소도, 목적지 변경도 없다
- 되돌릴 수 있으면 예측이 필요 없어진다. 이 게임은 예측형이다

**단, 오조작 방지는 UX 로 챙긴다.** 취소가 불가능하므로 **보내기 전에 목적지가 확실히 보여야** 한다
(목적지 미리보기 또는 짧은 확인 단계). **되돌리기가 아니라 오조작 방지**라 성격이 다르다.

### 전투 규칙

- **블로킹 없다.** 유닛은 적의 이동을 방해하지 않는다. 적은 유닛을 통과해 지나간다. (→ ADR-0003)
- 유닛은 **사거리 안의 적을 자동으로** 고른다. 플레이어가 타겟을 지정하지 않는다.
- 타겟 선택 규칙(프로토타입 고정): **보호대상에 가장 가까운 적** → 없으면 자신에게 가장 가까운 적.
  - *이유: "가장 가까운 적"만 쓰면 보호대상을 때리는 적을 무시하는 멍청한 상황이 나온다.*
- 적은 아군 유닛을 공격하는가? → **프로토타입 기본값: 공격하지 않는다.** 적의 목표는 오직 보호대상.
  - 나중에 "일부 적만 유닛을 공격"으로 확장 가능하게 열어 둔다.

### 행군 중 손실

- **프로토타입 기본값: 행군 중 유닛은 죽지 않는다.**
- 단, 이것은 **검증 대상**이다. `StageDefinition` 에 토글을 두어 켜고 끄며 플레이 테스트한다.
- 죽는 것으로 결정되면, 연출은 **사망이 아니라 후퇴/탈진**으로 한다 (톤 유지).

## 9. 마을 (Village)

- 맵에 **고정 배치**된다. 플레이어가 마을을 옮기거나 새로 짓지 않는다.
- 각 마을은 **고용 가능한 유닛 종류**와 **재고/쿨다운**을 갖는다.
- 마을의 위치가 **"이 방향은 몇 초 안에 커버 가능한가"** 라는 맵 판독 정보가 된다. → 난이도 조절 레버.
- **프로토타입: 마을 3개, 유닛 1종.**
  - *마을이 1개면 "어느 마을에서 보낼지"라는 판단이 사라지고, "마을이 커버하는 방향"이 맵 판독 정보로 기능하는지를 검증할 수 없다. 병종 다양화는 미루되 마을 수는 미루지 않는다.*
  - 종족별 병종·유닛 풀 리셋·영웅 지속성은 3단계 이후.
- 마을은 공격받지 않는다. (→ 미결정 D-02, 프로토타입 기본값 "아니오")

## 10. 자원

**단일 통화 = 고철(`Scrap`).** 로봇을 격파하면 흩어지는 부품을 모은 것이다 (→ §12 격파 연출).
중세~르네상스 기술 수준의 수인족이 대장간에서 무기를 만들고 강화하는 재료라 별도 설명이 필요 없다.

### 획득 경로 3가지 (2026-08-29 확정)

| # | 경로 | 성격 |
|---|---|---|
| ① | 스테이지 시작 시 초기량 + **시간당 자동 획득** | 수동 |
| ② | **적 처치 보상** | 능동 — 전투 결과가 자원에 반영된다 |
| ③ | **보호대상이 흘리는 고철을 터치해 회수** | 능동 — 플레이어가 보호대상을 계속 주시하게 만든다 |

> **~~"적 처치 보상은 프로토타입 범위 밖"~~ 은 폐기됐다** (→ ADR-0015).
> 옛 근거는 *"일부러 적을 흘려보내는 최적화가 생긴다"* 였으나, 이 게임에서는 성립하지 않는다 —
> **보호대상은 자동 이동하므로 적을 흘려보내면 그대로 맞는다.**
> 체력 100 에 실질 여유가 체감상 3칸 수준이라(→ §3) **체력을 고철로 환전할 여유 자체가 없다.**
> 흘려보내기는 이득이 아니라 즉시 손해다.

**⚠️ ③ 과 카메라 팬(§5)은 충돌한다.** 맵이 커지면 화면 밖에 떨어진 고철을 못 줍는다.
능동 조작을 늘리려던 장치가 "카메라를 계속 따라다녀야 하는 잡일" 이 될 수 있다.
→ 드랍 주기·유효 시간·미회수 시 소멸 여부를 정할 때 **팬과 같이 볼 것.**

### 소비처

**유닛 고용** · **유닛 업그레이드** (→ ADR-0009) · **지름길 개방** (→ §11) ·
**공병**(다리·장애물, → §11B) · **일회성 회복**

- **지속 힐러는 없다.** 유일한 패배 조건(보호대상 체력)을 상시 되돌리는 유닛이 있으면 패배 조건이 사라진다.
  회복은 **일회성 구매**라야 자원 지출 판단이 된다
- **밸런싱 기준선: `회복 1회 비용 > 장애물 1회 비용`.**
  예방이 복구보다 싸야 플레이어가 앞을 본다. 회복이 더 싸면 다들 맞고 고치는 쪽으로 최적화한다

### ⚖️ 난이도 배율은 적 체력에만 건다

출시 시 난이도 설정은 **적 체력 배율**만 조정한다. **적 데미지와 처치 보상에는 걸지 않는다.**
- 둘 이상 건드리면 난이도가 **곱**으로 움직여 예측이 불가능하다 (1.5 × 1.5 = 2.25배)
- 데미지를 올리면 *실수 한 번의 대가*만 커지지만, 체력을 올리면 처치 시간이 늘어
  **배치·재배치 판단 전체**가 어려워진다 → 이 게임이 시험하려는 것은 후자다
- 체력 1.5배 + 보상 1.5배면 난이도가 **안 바뀐다**

## 11. 지름길 기믹

- 맵에 지름길 엣지가 미리 정의되어 있고, **닫힌 상태**로 시작한다.
- 플레이어가 자원을 지불하면 열린다. 한 번 열면 계속 열려 있다.
- **보호대상만** 통과할 수 있다. 잡몹과 모체는 통과 불가 → 추격 거리가 벌어진다.
- 열리면 보호대상이 즉시 경로를 재계산해 지름길을 탄다.
- UI: 지름길 엣지 위에 클릭 가능한 마커. 비용과 잠금 상태 표시.

> **설계 의도:** "돈으로 시간을 산다". 병력에 쓸 자원을 지름길에 쓰면 방어가 얇아진다. 트레이드오프가 성립해야 한다.

### 지름길은 **비상 수단**이다 (2026-08-29)

- 지름길로 사이클을 건너뛰면 **배치해 둔 유닛이 버려진다.** 이 손실은 **그대로 둔다**
- 보호대상 체력이 낮을 때 **손해를 감수하고 도망치는 카드**다. 서사(도망가는 게임)와도 맞는다
- ⚠️ **비용이 유닛 손실보다 싸면 안 된다.** 비싸야 비상 수단이고, 싸면 기본 전략이 된다
- 사이클을 건너뛰면 **자원 획득도 건너뛴다**(적을 안 잡으므로) → 트레이드오프가 자동으로 성립한다
- **짧게 만든다.** 사이클 하나를 통째로 건너뛰는 크기면 안 된다
- **미리 보이는 쪽**으로 한다. 발견형(숨겨 두었다가 찾게 하는 것)은 즉흥적이라 예측형 성격과 어긋난다

## 11B. 공병 — 다리와 장애물 (→ ADR-0013)

**공병(`Sapper`)** 은 자원으로 사는 **일회성** 유닛이다. 다리 또는 장애물을 놓는다.

### 🔑 예외 없음 원칙 — 이 게임의 유일한 물리 법칙

> **모든 결과물은 마을에서 출발해 걸어서 도착한다.**
> 즉시 생성을 하나라도 허용하면 "그럼 유닛은 왜 걸어가야 하지" 가 따라온다.
> **예외 하나가 규칙 전체의 근거를 약화시킨다.**

- 공병도, 일회성 회복도 **걸어서 도착한다.** 즉시 발동은 없다
- **협곡 문제가 저절로 해결된다** — 아군 유닛이 못 건너면 공병도 못 건넌다. 상위 호환이 안 생긴다
- 즉시 발동은 *"맞고 나서 누른다"* 를 만들고, 도보 도착은 *"맞을 것 같으면 미리 보낸다"* 를 만든다.
  후자가 이 게임이 시험하려는 판단이다
- **지출 지점은 마을이 아니다.** 결제는 현장에서 일어난다. 중요한 것은 **결과물이 걸어서 도착한다**는 사실뿐이다
  (용병 대금도 선금이 아니라 임무 완료 보상이다).
  → 맵이 커지고 팬이 들어와도(§5) 마을로 카메라를 되돌리는 조작이 생기지 않는다

### 다리 — 아군 통로

- **아군 유닛이 지나갈 수 없는 지형(협곡 등)을 건너게 한다.** 배치 가능 영역, 즉 **공간에 투자**하는 것
- 적은 경로 그래프를 따르므로 다리와 무관하다
- **다리는 한 번 놓으면 스테이지 내내 남는다** (2026-08-29 확정). 사이클마다 다시 놓지 않는다.
  → *지형 변형* 이라는 논리와 일관된다. 따라서 다리는 **반복 비용이 아니라 초기 투자**이고,
  "지금 값을 치르고 남은 사이클 내내 쓸 것인가" 가 판단이 된다. 사이클 초반일수록 이득이 크다.
- ⚠️ **협곡 배치를 잘못하면 다리는 판단이 아니라 통행세가 된다.**
  건너편에 좋은 목이 하나뿐이고 거기 안 가면 못 막는 지형이면, 매번 같은 자리에 다리를 놓게 된다 — 절차지 선택이 아니다
- **판단이 되는 조건:** 협곡 이쪽으로도 막을 수는 있는데 **효율이 떨어지고**, 건너편 목이 **확실히 좋다**
  → 플레이어가 계산한다: *다리값 + 행군 시간을 치를 만큼 저쪽이 나은가.*
  → 사이클 초반이면 투자, 후반이면 시간이 없어 포기. **같은 지형인데 타이밍에 따라 답이 달라진다**

### 장애물 — 벽이 아니라 **시간 구매**

- 일정 체력이 있어 **적이 때려 부순다.** 그동안 적이 멈춘다
- 완전 차단이면 최적 위치가 하나로 굳는다. **시간 구매라야 "어디에 몇 초를 살 것인가"** 가 판단이 된다
- **놓는 타이밍이 핵심이다.** 적이 몰려온 뒤가 아니라 **다음 세대가 오기 전에 목을 미리 잠근다**
  → §5 의 사이클 구조와 정확히 맞물린다

> **⚠️ ADR-0003(블로킹 없음)의 예외다.** 아군 유닛은 적을 막지 않지만 장애물은 막는다.
> 근거: **장애물은 유닛이 아니라 지형 변형이다.** (→ ADR-0016)

### 다리 ≠ 지름길

|  | 다리 | 지름길 |
|---|---|---|
| 용도 | **아군 통로** | **보호대상 경로 단축** |
| 투자 대상 | **배치 가능 영역**(공간) | **경로 길이**(시간) |
| 적 통행 | 무관 | **불가** ← 그래야 투자 가치가 있다 |

## 11C. 버프 유닛 — 여우 수인(무희)

- **여우 수인(`FoxFolk`) / 무희** — 주변 아군에게 **공격속도 버프**를 준다
- **유닛형이다.** 다른 병종처럼 마을에서 고용 → 행군 → 배치 → 재배치한다.
  고정 설치물(토템)이 아니다 — 모체가 이동하는 게 핵심인 게임에서 고정물은 금방 무용지물이 된다
- **버프는 범위를 갖는다.** 그래서 판단이 하나 더 생긴다:
  전선이 밀릴 때 **딜러만 옮길까, 버프까지 통째로 옮길까.**
  → 버프가 **재배치를 유발하는 이유**가 된다

**미결:** 버프 **중첩 규칙** · 성직자(회복 계열 버프?)를 낼지 여부와 그 종족
⚠️ 공격속도 버프는 **DPS 를 곱으로 밀어올린다.** 업그레이드와 겹칠 때 체감 난이도가 급변한다.

> **⚠️ 서사와의 정합성은 기획자 영역이다.** §부록 A 의 "첫 만남 = 고양이 수인과 쥐 수인" 에
> 여우 수인이 어떻게 등장하는지는 개발이 정하지 않는다.

## 12. 시각 톤 (참고용 — 프로토타입 범위 밖)

## 14. 프로토타입 통과 조건

아래 4개를 눈으로 확인해야 다음 단계로 간다. **하나라도 안 되면 기획을 갈아엎는다.**

1. **배치 타이밍을 놓쳤을 때 "아깝다"는 감정이 발생한다.**
2. 모체가 이동해서 기존 배치가 무의미해지는 순간이 **명확히 체감된다.**
3. 보호대상이 3번째 마을에 닿기 *전에* 미리 고용하게 된다 (= 예측형 플레이 발생).
4. 지름길을 열지 말지 실제로 고민하게 된다.

## 15. 영웅 (`Hero`) — 존재는 확정, 설계는 미정

**스토리의 핵심 인물이다.** 2026-08-29 확정: *"스토리 핵심 인물인데 당연히 살아있지."*

**지금 확정된 것은 "존재한다" 뿐이다.** 아래가 정해지기 전에는 구현하지 않는다:

- **보호대상(`Escortee`)과 같은 인물인가, 별개인가** — 같으면 지켜야 할 대상, 다르면 플레이 가능한 유닛
- **스테이지 간 연속성**을 영웅이 담당하는가 (현재 이 게임에는 스테이지를 관통하는 것이 없다)
- **즉시 발동 능력**을 영웅에게 둘 것인가
  → ⚠️ **ADR-0013(모든 결과물은 걸어서 도착)의 예외를 만드는 일이다.**
    허용하려면 ADR 이 필요하다. *"영웅은 이미 판 위에 있으므로 새로 생성되는 것이 아니다"* 는
    논리가 성립할 수는 있으나, 검토 없이 넣지 마라
- 영웅이 죽으면 패배 조건이 둘이 되는가 (현재는 보호대상 체력 하나뿐 — §3)

**서사·대사·인물 설정은 기획자 영역이다.** 이 문서가 정하는 것은 **시스템 경계**까지다.

→ 태스크: `TASKS-P2.md` Q-15

## 부록 A. 서사 (참고 — 구현 범위 밖)

인류 멸망 후의 지구. 냉동 동면에서 깨어난 소년이 무언가에 이끌려 달린다. 소년의 생체 신호에 반응해 가동된 로봇들이 그를 쫓는다. 숲을 부수며 몰려드는 로봇을 경계한 지구의 새 주인들(수인 종족)이 소년을 돕는다.

- 보호대상 = 소년, 모체 = 이동하는 공장, 잡몹 = 로봇, 마을 = 수인 종족의 정착지.
- 언어 장벽: 소년은 고대 인간어를 쓴다. 이해도가 관계 지표로 상승한다.
- 어두운 세계관은 **수집형 텍스트에만** 노출하고 본편 서사에는 넣지 않는다.
- 종족은 **기능적 차별화**(후각 정찰 / 활공 / 굴착 등 지형 제약)와 연결되어야 한다. 안 그러면 수인 설정이 그냥 미술 취향으로 읽힌다.
