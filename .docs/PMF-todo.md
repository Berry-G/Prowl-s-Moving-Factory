## 🔴 BLOCKER — 착수 전 반드시 해결

프로토타입 코드를 짜기 전에 닫아야 하는 항목입니다. 아래 3번(설계 결정)은 게임 성격 자체를 결정하므로, 이게 안 정해지면 유닛 상태머신을 설계할 수 없습니다.

### 1. 팀 계약 `[합의]`

2인 인디팀이 깨지는 가장 흔한 원인입니다. 코드 한 줄 쓰기 전에 문서로 남기세요.

- [ ] 수익 배분 비율 확정
- [ ] 저작권 귀속 주체 확정 (공동 vs 단독 명의)
- [ ] 중도 이탈 시 처리 방식 (작업물 귀속, 잔여 지분)
- [ ] 의사결정 권한 범위 명문화 — 현재 암묵적으로 "기획자가 게임 디자인 veto, 개발자가 구현·기술 결정"으로 운영 중
- [ ] 전문가 검토 의뢰 (※ 저는 변호사가 아니므로 실제 계약서는 반드시 검토받으세요)

### 2. 컨셉 원페이저 `[합의]`

- [ ] 게임을 한 문장으로 정의
- [ ] **통과 조건: 두 사람이 그 한 문장을 각자 말했을 때 같은 문장이 나온다**
- [ ] 안 나오면 뒤 단계 전부 터집니다. 여기서 며칠 쓰는 게 남는 장사입니다

### 3. 미해결 설계 결정 `[합의]` — ✅ 해소됨 (2026-08-25)

**착수를 막던 결정들은 전부 닫혔습니다.** 아래 4건이 확정되어 유닛 상태머신 설계가 가능해졌습니다.

| 결정 | 결과 | 근거 |
|---|---|---|
| 배치 조작 모델 | **마을 고용 + 행군** | `adr/ADR-0001` |
| 맵 격자 / 뷰 | **직교 격자**, 쿼터뷰는 표현 계층에서만 | `adr/ADR-0002` |
| 블로킹 여부 | **없음** (순수 사격형) | `adr/ADR-0003` |
| 적 이동 | **경로 그래프 + 통행 권한**, 지름길은 보호대상 전용 | `adr/ADR-0004` |

나머지 세부 결정(뒤에 남은 유닛 처리, 마을 피격, 행군 중 사망 등)은 **프로토타입을 막지 않습니다.**
전부 `StageDefinition` 토글로 구현해 두고 플레이 테스트에서 결정합니다 → `GDD.md` §13 (D-01 ~ D-06)

- [ ] D-03(행군 중 유닛 사망) 관찰 — **프로토타입 1순위**. 유닛 손실은 사망이 아니라 **후퇴/탈진**으로 연출
- [ ] D-01, D-06 도 같은 세션에서 판정 → 결정 시 ADR 추가

### 4. 내레이터 형식 `[합의]`

- [ ] 하이브리드 안에 대한 기획자 동의 확보
