## 4. 확정된 규칙 (뒤집지 마라 — 사용자 지시)

`CLAUDE.md` §2 의 6개에 더해 이번 세션에서 확정된 것들이다.

1. **마을은 2개다.** (10,13) 서쪽 / (27,9) 동쪽.
2. **아군은 도로를 건널 수 없다.** 도로는 보호대상·모체·적의 통행로다.
3. **도로와 장애물이 아니면 어디든 배치할 수 있다.** 격자가 남아 있는 이유는
   **겹치기를 막기 위해서**다 (한 칸 한 유닛). 제약을 걸고 싶으면 장애물을 놓아서 건다.
4. **이동 경로는 타일 단위가 아니어도 된다.** 장애물 모서리를 스치며 우회한다.
5. **보호대상은 앞으로만 간다.** 이미 지나친 지름길로 되돌아가지 않는다 (구매는 가능).
6. **UI 가 뜨면 0.1배속.** 고용 패널·지름길 구매 패널 모두 같은 규칙.
7. **쥐 수인은 마법사다.** 매직 미사일을 쏜다. 단 **피해는 히트스캔(즉시)** 이다 —
   도착해야 맞는 방식으로 바꾸면 사거리·간격 밸런스를 전부 다시 잡아야 한다.
8. **로봇은 2종까지.** 특수 능력 금지 (G-18 명시).

## 5. ⚠️ 함정 — 같은 실수를 두 번 하지 마라

### 5-1. 씬을 다시 만들면 손으로 붙인 것이 전부 날아간다

`PMF/Create Greybox Scene` 은 씬을 **새로 만든다.** 코드가 만들지 않는 것은 사라진다.
이번 세션에 **두 번** 당했다.

- `SelectionController` 가 씬 빌더에 없어서 재구축 후 **유닛 선택·이동·회수·강화가 전부 죽었다.**
- `GreyboxFactory.CreateStageDefinition` 이 매번 모든 필드를 다시 써서
  **G-21 속도 조정이 통째로 원복됐다.** 병종도 낡아서 `Ally_Basic` 을 새로 만들고
  마을 배선을 1종으로 되돌렸다.

→ 지금은 둘 다 고쳤다. **팩토리는 초기값만 심고 기존 에셋은 건드리지 않는다.**
→ 새 컴포넌트를 씬에 붙였으면 **반드시 `SceneParts` 에도 추가하라.**
→ 씬 재구축 뒤에는 **`SelectionController` 존재와 스테이지 SO 값을 확인**하고 넘어가라.

### 5-2. 씬 재구축은 반드시 편집 모드에서

플레이 모드 중에 `PMF/Create Greybox Scene` 을 부르면 조용히 실패한다
(`EditorSceneManager.NewScene` 이 플레이 중에는 안 된다). `editor_stop` 먼저.

### 5-3. Unity CLI 파이프라인이 통째로 먹통이 된다

`unity status` 는 `ready` 인데 **모든 `unity command` 가 30초 타임아웃**. 고장이 아니다.
이번 세션에 3번 발생했다. 복구법은 `mem:unity_cli` 에 적어 뒀다 — 요약하면
**MCP(`Unity_RunCommand`)로 우회해 도메인 리로드를 걸면 즉시 되살아난다.**

또한 **플레이 모드에서 `run_tests` 를 돌리지 마라.** `TestJobRunner` 가 깨져 이 증상을 만든다.

### 5-4. `eval` 의 짧은 출력은 진단을 가린다

컴파일 실패 시 마지막 진단만 보여준다. `Unreachable code detected` 만 뜨면
**진짜 에러가 그 앞에 숨어 있는 것**이다. `--json` 을 붙여 전문을 봐라.

Unity 6000.5 기준으로 실제로 걸린 것들:
`GetInstanceID()` → 폐기 / `FindObjectsSortMode` → **열거형 자체가 폐기** /
`using` 문은 스크립트 맨 앞에 못 쓴다 / `HireableUnits.Count` 는 메서드 그룹이다.

### 5-5. `capture_game_view --save_path` 는 프로젝트 밖을 거부한다

상대 경로는 `Assets/` 아래로 강제된다. `Temp/x.png` → `Assets/Temp/x.png` 에 저장된다.
`CLAUDE.md` §4 "Assets 최상위 새 폴더 금지" 위반이므로 **다 보고 나서
`delete_asset --asset Assets/Temp --confirm true` 로 반드시 지워라.**

### 5-6. `CLAUDE.md` §3 의 API 표가 낡았다

`FindObjectsByType<T>(FindObjectsSortMode.None)` 을 쓰라고 되어 있는데
**Unity 6000.5 에서 `FindObjectsSortMode` 는 폐기됐다** (CS0618).
인자 없는 오버로드가 정렬하지 않는 기본 동작이다.
코드는 고쳤지만 **규칙 파일은 사용자 확인을 기다리며 안 고쳤다.**

## 8. 검증 루프 (그대로 따라라)

```bash
unity status --no-banner                      # ready 확인
unity command recompile --no-banner           # → recompile_status 로 폴링
unity command console --tail 40 --level warning --no-banner
unity command run_tests --mode EditMode --no-banner     # ⚠️ 편집 모드에서만
```

- EditMode 테스트는 **32개 전부 통과**가 기준선이다.
- 콘솔을 볼 때 `clear_console` 은 **CLI 버퍼를 비우지 못한다.** 낡은 항목이 계속 보이므로
  **타임스탬프로 걸러라.**
- 플레이 중 계측은 `EditorApplication.Step()` 으로 프레임을 돌린다 (`mem:unity_playmode_frame_freeze`).
  한 번에 900스텝 정도가 5초 예산 안에 들어온다. 넘으면 타임아웃이 뜨지만 **작업 자체는 완료된다.**
